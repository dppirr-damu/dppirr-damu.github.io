# Порядок еженедельного обновления дашборда

Ответственный департамент — **Департамент по продвижению программ и регионального развития** Фонда «Даму».

## Как сотруднику обновить свою программу (без правки кода)

1. Открыть `damu-nefinansovaya-podderzhka.html` в браузере.
2. В меню слева выбрать свою программу → кнопка **«Редактировать»**.
3. Заполнить: статус, описание, показатели (**факт и план** — план нужен для диаграммы),
   географию, этапы и их даты, вывод для совещаний.
4. Нажать **«Сохранить»** — данные сохранятся в браузере (localStorage).
5. Нажать **«Экспорт»** в верхней панели — скачается файл `damu-data-ГГГГ-ММ-ДД.json`.
6. Отправить этот JSON ответственному за панель (в чат или на почту).

Коллеги могут посмотреть ваши данные через **«Импорт»** → выбрать ваш JSON.
На странице «Обзор» кнопка **«Изменить дату и сводные KPI»** обновляет дату актуальности
и суммарные показатели портфеля. Там же — **«Сбросить все данные»** (возврат к значениям,
зашитым в HTML-файл).

> Важно: сохранение работает только в текущем браузере. Чтобы изменения увидели все,
> данные нужно передать ответственному через «Экспорт».

## Роль ответственного за панель

1. **Пятница** — собрать JSON-файлы от сотрудников по всем 8 программам.
2. Открыть панель, загрузить каждый файл через «Импорт», проверить цифры.
3. Обновить дату и сводные KPI («Изменить дату и сводные KPI» на странице «Обзор»).
4. **Выпустить новую версию для рассылки:** открыть HTML-файл в редакторе
   и заменить содержимое блока `const DEFAULT_DATA = { … };` на итоговые данные
   (их можно взять из экспортированного JSON — структура совпадает).
   Исходные JSON сотрудников сохранить в `data/archive/`.
5. Разослать обновлённый HTML коллегам. Дата актуальности в шапке показывает свежесть данных.

## Как устроены данные

Все данные — один JSON-объект (и в HTML в `DEFAULT_DATA`, и в экспортируемом файле):

```json
{
  "date": "14.11.2026",
  "kpi": { "participants": "—", "regions": "—" },
  "programs": [
    {
      "name": "Название программы",
      "status": "active",
      "desc": "1–2 предложения о сути.",
      "reach": [["Показатель", "факт", "план"]],
      "geo":   [["Показатель", "значение"]],
      "stages": [{ "name": "Этап", "state": "done", "date": "01.09.2026" }],
      "conclusion": "Одна формулировка для совещания."
    }
  ]
}
```

- **status:** `active` — «Реализуется», `process` — «Набирает обороты», `plan` — «Планируется».
- **state этапа:** `done` — выполнен, `now` — в работе, `next` — впереди.
- **reach:** третий элемент — план; диаграмма строится только по строкам,
  где факт и план заполнены числами.

## Диаграммы для презентаций

На странице каждой программы — карточка **«Выполнение плана»** с барами факт/план
и процентом выполнения. Карточка самодостаточна: содержит название программы и дату
данных, поэтому её можно просто заскриншотить для слайда.

## Правила достоверности

- **Никаких выдуманных или экстраполированных цифр.** Если значения нет — ставится `—`.
- Описание ≤ 2 предложений, вывод ≤ 1 предложения — остальное цифры.
- Ответственные за данные по каждой программе назначаются поимённо
  (см. открытый вопрос №2 в PRD).

## Папки

- `data/inbox/` — сюда кладутся присланные JSON-файлы и иные данные недели.
- `data/archive/` — архив обработанных данных по неделям.
