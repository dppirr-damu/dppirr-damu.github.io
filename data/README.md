# Порядок обновления дашборда

Ответственный департамент — **Департамент по продвижению программ и регионального развития** Фонда «Даму».

Основной способ — **общая Google Таблица**: сотрудники заполняют её одновременно,
сайт подтягивает изменения автоматически (задержка — около 5 минут).

## Первоначальная настройка (один раз, ответственный за панель)

1. Загрузить шаблон [`data/template/Даму_дашборд_данные.xlsx`](template/) в Google Диск
   и открыть как Google Таблицу (**Файл → Сохранить как Google Таблицу**).
2. Выдать сотрудникам доступ на редактирование (**Настройки доступа → Редактор**).
   По желанию — защитить листы: **Данные → Защищённые листы и диапазоны**,
   чтобы каждый сотрудник мог менять только лист своей программы.
3. Опубликовать таблицу: **Файл → Поделиться → Опубликовать в интернете →
   Весь документ → Microsoft Excel (.xlsx) → Опубликовать**. Скопировать ссылку.
4. Вписать в HTML-файл дашборда, блок `const SHEET`:
   - `pubUrl` — ссылка из п. 3;
   - `editUrl` — обычная ссылка на таблицу (из адресной строки).
5. Отправить изменённый файл в репозиторий. После этого кнопки «Редактировать»
   на сайте ведут в таблицу.

> Ограничение: опубликованная таблица доступна на чтение любому, у кого есть ссылка,
> как и сам сайт на GitHub Pages. Публиковать только сведения, допустимые к открытому доступу.

## Как сотруднику обновить свою программу

1. Открыть Google Таблицу (или кнопку **«Редактировать в таблице»** на странице программы).
2. Перейти на лист своей программы (`01 …` — `08 …`).
3. Менять значения в **жёлтых ячейках**. Колонку «Раздел» не переименовывать.
4. Новая строка показателя или этапа: вставить строку и выбрать «Раздел» из списка.
5. Изменения появятся на сайте в течение ~5 минут. Кнопка **«Обновить»** на сайте
   загружает данные сразу (с учётом задержки публикации Google).

## Структура таблицы

| Лист | Содержимое |
|---|---|
| `Инструкция` | Правила заполнения и образец формата |
| `Сводка` | Дата актуальности, участников всего, регионов охвата — заполняет ответственный |
| `01 …` — `08 …` | По листу на программу; порядок на сайте — по номеру в названии листа |

Колонки листа программы: **Раздел | Показатель / этап / текст | Факт / значение / статус этапа | План / дата этапа**.

| Раздел | Колонка B | Колонка C | Колонка D |
|---|---|---|---|
| Название | Название программы | — | — |
| Статус | Реализуется / Набирает обороты / Планируется | — | — |
| Описание | 1–2 предложения | — | — |
| Охват | Показатель | Факт (число) | План (число) |
| География | Показатель | Значение | — |
| Этап | Название этапа | Выполнен / В работе / Впереди | Дата ДД.ММ.ГГГГ |
| Вывод | Одна формулировка для совещания | — | — |

Диаграмма «Выполнение плана» строится по строкам «Охват», где факт и план — числа.
Строки с другим текстом в колонке «Раздел» (пояснения, заметки) сайт игнорирует.

## Если таблица недоступна

Сайт показывает последнюю успешно загруженную копию (в этом браузере) или данные,
встроенные в HTML-файл, и помечает это в шапке: «Таблица недоступна».

## Резервный способ (без таблицы)

Пока `pubUrl` пустой, панель работает по-старому: сотрудник нажимает «Редактировать»,
сохраняет, делает «Экспорт» JSON и отправляет ответственному; ответственный загружает
файлы через «Импорт» и обновляет блок `DEFAULT_DATA` в HTML-файле.

## Правила достоверности

- **Никаких выдуманных или экстраполированных цифр.** Если значения нет — ставится `—`.
- Описание ≤ 2 предложений, вывод ≤ 1 предложения — остальное цифры.
- Ответственные за данные по каждой программе назначаются поимённо
  (см. открытый вопрос №2 в PRD).

## Папки

- `data/template/` — шаблон Google Таблицы.
- `data/inbox/` — присланные данные недели (в репозиторий не попадают).
- `data/archive/` — архив обработанных данных (в репозиторий не попадают).
