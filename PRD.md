# PRD — Единая информационная панель по программам нефинансовой поддержки Фонда «Даму»

| **Версия** | 1.0 |

| **Статус** | Утверждён концепт; MVP реализован |

---

## 1. Контекст и проблема

Департамент нефинансовой поддержки Фонда «Даму» реализует 11 программ и направлений. Данные по статусу их реализации регулярно требуются коллегам из других департаментов:

- при срочных запросах на совещаниях;
- при подготовке к встречам с третьими лицами;
- при участии в интервью и публичных выступлениях.

**Проблема:** на текущий момент получение актуальных данных возможно только через прямое обращение к сотрудникам департамента. Это создаёт задержки, отвлекает сотрудников от текущих задач и повышает риск предоставления неактуальных или неполных сведений.

## 2. Цель проекта

Создать единую точку доступа, где любой сотрудник Фонда может в любое время самостоятельно получить актуальную, структурированную информацию по статусу любой программы нефинансовой поддержки — без обращения к сотрудникам профильного департамента.

**Измеримый результат:** 100% типовых запросов о статусе программ закрываются самостоятельно через панель; обращения к департаменту требуются только для нестандартных запросов.

## 3. Целевая аудитория

| Группа | Сценарий использования |
|---|---|
| Сотрудники других департаментов | Быстрый доступ к статусу и цифрам по программе на совещании, встрече, в интервью |
| Руководство Фонда | Сводная картина по всему портфелю нефинансовой поддержки |
| Департамент нефинансовой поддержки | Единый источник актуальных данных; снижение входящих разовых запросов |

## 4. Область охвата

**Входит:** 11 программ нефинансовой поддержки, показатели охвата и участников, география, статус и этапы реализации, выводы по каждой программе.

**Не входит (на данном этапе):** финансовая поддержка (кредиты, гарантии, субсидирование ставки), бюджетные показатели программ, персональные данные участников, интеграция с внутренними информационными системами Фонда.

### Перечень программ

2. Арманнан Иске
3. Онлайн-курсы
4. Мобильный фронт-офис
5. Единый фронт-офис

## 5. Продуктовое решение

**Формат:** живой интерактивный дашборд (HTML-страница, открывается в браузере), закреплённый в боковой панели рабочего ассистента и доступный для рассылки как файл.

**Ключевая логика:** данные собираются департаментом, обновляются в панели еженедельно, анализируются (статус, динамика этапов) и представляются с готовым выводом по каждой программе.

**Стиль подачи:** официально-деловой, с акцентом на цифры, данные и статус реализации. Минимум описательного текста — максимум проверяемых показателей.

## 6. Функциональные требования

### 6.1. Структура панели

| № | Блок | Содержание |
|---|---|---|
| FR-1 | Шапка | Название Фонда и продукта, дата актуальности данных, пометка о еженедельном обновлении |
| FR-2 | Сводные KPI | Число программ; суммарный охват участников; число регионов охвата; число программ в активной стадии |
| FR-3 | Сводная таблица | По каждой программе: статус, главный показатель охвата, география — одной строкой для быстрого сканирования |
| FR-4 | Карточки программ | Отдельный блок по каждой из 11 программ (см. 6.2) |
| FR-5 | Подвал | Ответственный департамент, порядок уточнения показателей |

### 6.2. Карточка программы (единый шаблон для всех 8)

Каждая карточка обязательно содержит:

- **Статус реализации** — один из трёх: «Реализуется», «Набирает обороты», «Планируется» (цветовая индикация).
- **Описание** — 1–2 предложения о сути программы.
- **Охват и участники** — 2–4 количественных показателя (например: обучено, проконсультировано, запущено бизнесов, план на год).
- **География** — число регионов/городов/маршрутов, формат присутствия.
- **Этапы реализации** — 3 этапа с индикацией: выполнено / в работе / впереди, с датами.
- **Вывод** — одна готовая формулировка для использования на совещании или в интервью.

### 6.3. Актуализация данных

| № | Требование |
|---|---|
| FR-6 | Данные обновляются еженедельно; дата актуальности отображается в шапке панели |
| FR-7 | Источник данных — департамент нефинансовой поддержки; формат приёма: текст, Excel, Word, PDF |
| FR-8 | Еженедельное автоматическое напоминание ответственному о присылке свежих показателей (настроено: пятница, 09:00) |
| FR-9 | Не выдумывать и не экстраполировать цифры: показатель без подтверждённого значения отображается как «—» |

### 6.4. Доступность

| № | Требование |
|---|---|
| FR-10 | Панель открывается в любом браузере без установки ПО и без доступа к внутренним системам |
| FR-11 | Файл можно пересылать коллегам; данные внутри статичны до следующего обновления |
| FR-12 | Адаптивная вёрстка: читаемость на ноутбуке и планшете |

## 7. Нефункциональные требования

- **Достоверность:** все цифры — только из подтверждённых данных департамента; без интерполяции.
- **Скорость обновления:** от получения данных до обновлённой панели — не более 1 рабочего дня (фактически — минуты в рабочей сессии).
- **Единый стиль:** официально-деловой язык, единообразие терминов и единиц измерения по всем программам.
- **Автономность файла:** панель — один HTML-файл без внешних зависимостей, открывается офлайн.

## 8. Процесс работы (workflow)

1. **Еженедельно (пт, 09:00)** — автоматическое напоминание ответственному сотруднику департамента.
2. **Сотрудник присылает** свежие показатели по программам в чат (любой формат).
3. **Панель обновляется** — цифры, статусы, этапы, дата актуальности; выводы при необходимости переформулируются.
4. **Коллеги используют** актуальную версию на совещаниях, встречах и в интервью.

## 9. Метрики успеха

| Метрика | Целевое значение |
|---|---|
| Доля типовых запросов к департаменту по статусу программ | Снижение до ~0 |
| Актуальность данных в панели | Не старше 7 дней |
| Полнота заполнения показателей | 100% программ с заполненными охватом, географией и статусом |
| Время получения информации коллегой | < 1 минуты (открыть файл → найти программу) |

## 11. Риски и ограничения

| Риск | Митигация |
|---|---|
| Данные не присылаются вовремя | Еженедельное автонапоминание; дата актуальности в шапке сигнализирует о «свежести» |
| Рассылка файла создаёт устаревшие копии | Указание даты актуальности; рекомендация использовать закреплённую живую версию как источник |
| Показатели разных программ несопоставимы | Единый шаблон карточки; сопоставление только в рамках своего блока |
| Перегрузка карточек текстом | Правило: описание ≤ 2 предложений, вывод ≤ 1 предложения, остальное — цифры |
